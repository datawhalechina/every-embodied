# 机器人上下文设计与实践模板

本页用离线记录练习设计决策上下文，不需要机器人或模型 API。目标是检查一条观测是否足以支持下一步决策，并用一致字段记录执行反馈。

## 1. 定义输入与边界

为每次决策记录：任务目标、阶段、传感器时间戳、坐标系和单位、机器人状态、可用工具、动作约束、最近一次执行结果以及成功判据。视觉坐标和机器人坐标必须说明变换来源；对失效或过期的观测显式标记，而不是沿用旧值。

```yaml
任务: 将杯子扶正并把纸巾放入杯中
阶段: 确认杯子姿态
观测:
  时间戳: 2026-01-01T00:00:00Z
  相机: wrist_camera
  图像: observation_001.png
  坐标系: robot_base
  单位: m
机器人:
  末端位置: [0.30, 0.10, 0.15]
  夹爪状态: open
  持物: false
可用动作: [observe, move, grasp, place, stop]
约束: 使用当前设备已验证的工作空间和速度限制
上次结果: 尚未执行
完成判据: 杯口朝上，纸巾位于杯内
```

这是教学示例，坐标和动作名称不对应具体设备。部署时须由实际接口、标定和控制器提供有效范围。

## 2. 决策循环

```text
获取带时间戳的观测 → 检查数据有效性 → 更新任务与历史状态
→ 选择动作或要求重新观察 → 执行并记录结果 → 验证 → 继续 / 恢复 / 停止
```

每轮记录 `观察引用、决策理由、动作及参数、执行返回、验证结果、下一状态`。历史中保留影响下一步的事件，例如抓取失败、物体移动、标定更新；将冗长日志留在外部，按需检索，避免只压缩掉关键失败信息。

## 3. 离线练习

1. 选取一段自己的操作视频或公开轨迹，标记目标、子任务、关键接触和失败时刻。
2. 在三个关键时刻填写上面的上下文，列出能支持下一步的观察以及缺失信息。
3. 分别写出“继续动作”和“重新观察”的条件。检查图像与状态时间是否对应、坐标变换是否有依据。
4. 用同一段轨迹对比完整历史与简短事件摘要，记录各自是否保留目标位置变化和失败原因。
5. 给出任务完成判据，并人工检查最后一帧或轨迹，记录不确定的情况。

建议提交：三份上下文记录、一份事件摘要、关键帧与来源、判据及人工核对结果。此练习检验的是信息组织，不声称模型或机器人实际完成任务。

## 4. 继续扩展

在同一任务和评测协议下比较固定历史窗口、事件摘要和外部记忆检索，分别记录任务成功率、决策延迟和上下文长度。若没有真机，可先在仿真或离线轨迹上完成；任何数值结论都应给出任务、样本数与重复方式。
