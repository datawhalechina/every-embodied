# 01 从稳定供电开始连接 Aura

完成本章后，应能解释每个接口的用途，通过局域网读取设备状态，并在失联时区分供电、启动、无线网络与应用服务问题。准备一台电脑、Aura、适配本机型的电源和一根确认支持数据的 Micro USB 线。学习过程中先保持底盘静止。

## 1.1 认识这台机器

本专题使用 FrontierX Aura 的 RDK X5 样机。Aura 产品还存在其他计算平台配置；以下 ROS 2、BPU 和串口说明以 X5 样机为对象。前脸有固定仰视相机与圆形显示区域，两侧是差速轮。可用工作包括表情显示、语音交互、视觉识别、轮式移动，以及通过网络向其他执行器交接任务。

圆屏外观不等于有触摸屏。屏幕是否支持触控需看具体硬件；我们使用的样机没有通过触屏输入完成调试。相机也没有可以软件俯仰的云台，改变机身朝向只能改变水平视线。低处障碍物和地面目标需要额外的视野与传感器设计。

## 1.2 为什么亮着却连不上

样机曾长时间表现为屏幕亮、热点间歇出现、USB 键鼠不亮、服务无法连接。替换供电后恢复。这个实例说明：屏幕点亮只说明部分电路获得供电，不能据此判断 X5 已正常启动。

先检查输入电源和线缆，再查系统。RDK X5 开发板文档要求 5 V / 5 A 等级的供电；整机外部电源应按 Aura 机身标注及供应方说明选择，不能把开发板规格直接当作整机所有接口的输入规格。外壳电源线、内部板卡电源口与调试口要分别确认。

| 看到的接口 | 本专题中的用途 | 如何判断连接成功 |
| --- | --- | --- |
| 整机供电接口 | 为机器人供电，样机有触碰开关交互 | 系统完整启动、设备持续在线 |
| X5 调试 Micro USB | 板上 USB 转串口调试，合作方指定 | 电脑出现新的串口，终端收到启动文字 |
| 板上 USB Host | 键鼠、外设 | 系统枚举到 USB 设备 |
| 网口 | 接入有 DHCP 的有线局域网 | 路由器分配 IP，SSH / SDK 可达 |
| Wi-Fi | 热点配置或加入家庭/实验室网络 | 路由器设备列表、SSH 和 SDK 都可检查 |

外部 Type-C 的具体信号取决于整机接线，不能仅凭形状认定它就是 ADB、串口或网卡。Micro USB 串口用于登录和修网络，SDK 的主通信仍可走局域网。

## 1.3 串口救援与 Wi-Fi 配置

1. 用数据线连接合作方指定的 X5 Micro USB 调试口；在电脑设备管理器查看“端口（COM 和 LPT）”。拔插前后新增的 COM 号才是本次候选。
2. 串口终端选择 **115200、8N1、无流控**。打开后按回车；需要观察启动日志时保持终端打开，再正常启动整机。
3. 使用随设备提供的账号登录。账号、密码与网络密钥不写进开源仓库。
4. 登录后先读状态，再配置网络。下列命令运行在机器人上：

```bash
uname -a
ip -br address
nmcli device status
nmcli device wifi list
nmcli --ask device wifi connect 'YOUR_WIFI_SSID'
ip route
```

`--ask` 在终端交互输入密码，避免密码落进教程与命令历史。只有机器实际使用 NetworkManager 时才使用 `nmcli`；固件提供专用配网工具时按该版本说明执行。

电脑和机器人最好加入同一个路由器。这样电脑继续通过原网络上网，SDK 通过机器人局域网 IP 访问，不必反复切换到 Aura 热点。初次配网可短时接热点；AP 隔离、访客网络和不同 VLAN 可能使同一 SSID 下的设备仍无法互访。标准热点地址 `192.168.4.1` 是客户端默认值，加入路由器后改用路由器分配的 IP。

## 1.4 电脑端检查连接

在本专题 `code` 目录建立环境，Python 要求 3.11 及以上：

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell 使用：.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m aura_robot.debug --host YOUR_ROBOT_IP probe --output artifacts/probe.json
```

`probe` 读取 daemon、媒体、运动、应用与 WebSocket 状态。预期得到逐项状态和 JSON；返回非零时打开报告，看具体失败项。HTTP 可达与相机有新画面需要分别验收。

PowerShell 可先检查端口，Linux 可先检查路由：

```powershell
Test-NetConnection YOUR_ROBOT_IP -Port 8765
```

```bash
ip route get YOUR_ROBOT_IP
ssh YOUR_USER@YOUR_ROBOT_IP
```

## 1.5 在线、相机与温度分开检查

SSH 登录机器人后记录系统运行时间、服务列表和温度：

```bash
uptime
systemctl --user --failed
systemctl --user list-units --type=service --all
for f in /sys/class/thermal/thermal_zone*/temp; do printf '%s ' "$f"; cat "$f"; done
```

thermal 数值通常以毫摄氏度表示，例如 `65000` 对应 65 °C；对应哪个传感器还要查看相邻的 `type`。历史样机曾观察到高温，供电修复后的温度是另一次观测，不能用历史值回答当前温度。长时间运行先检查散热、温度趋势、降频/重启日志，再决定是否保留高负载相机和算法。

固件可能使用用户级 AuraOS 服务，也可能保留旧 ROS 启动服务。先看实际列表；不要按旧文章同时启动两套串口持有者。相机桥、自建 battery 扩展与原生固件服务同样要区分。

正常结束调试，先停止本次动作与自建任务，再通过系统关机入口关闭，等系统停止后断电。开源练习不把拔电作为常规结束步骤。
