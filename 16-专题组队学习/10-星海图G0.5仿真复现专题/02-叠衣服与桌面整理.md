# 02 · RoboDojo 叠衣服与桌面整理

在一组固定场景中运行三种控制方法，并比较原生成功条件、过程分数和控制步数。三组都使用原生场景布局及同一评测通道。[小红书完整版](https://www.xiaohongshu.com/explore/6ad2e41a0000000015014966?xsec_token=ABzE4Vr7EXL0p7MRPAA9JzcUswNHzKqMLni0Y0fK8A5L0=&xsec_source=pc_user) · [B 站完整版](https://www.bilibili.com/video/BV1HMJY61ENP/)

## 从相机到原生分数

1. 按 [固定场景清单](data/fold/case-plan.json)创建回合。 `eval_seed` 选场景组，`layout_id` 选组内固定布局。每种方法从对应场景独立开始。
2. 读取高位相机、左右腕相机、14 维机器人状态和原生指令。两臂各占 6 个关节值和 1 个夹爪开度。
3. 仅 G0.5 组用同一个策略生成 16 步候选，每段送最多 15 步给仿真后重新观察。仅上层推理组直接使用可记录的控制工具。组合组用同一 G0.5 检查点生成候选，上层可接收动作、执行更短的前缀或做有界末端修正。
4. 用原生任务判定读取终局成功和部分得分。桌面整理上限 1,000 步，叠衣服上限 500 步。原生成功与平均原生得分分别统计。

| 任务 | 仅 G0.5 | 仅上层推理 | 组合 |
| --- | ---: | ---: | ---: |
| 叠衣服成功数 | 1/5 | 1/5 | 5/5 |
| 叠衣服平均原生分 | 0.24 | 0.28 | 1.00 |
| 桌面整理成功数 | 0/5 | 0/5 | 0/5 |
| 桌面整理平均原生分 | 0.35 | 0.65 | 0.70 |

10 个完整配对场景中，组合在 4 个场景的得分高于两个单方法。6 个调试回合保留在[逐回合数据](data/fold/episodes.csv)，统计时按阶段筛选。各组是本教程的固定场景实验，官方公开报告中的 π0.5 组合只用于确定场景。

## 为什么要在同一布局比较

衣角位置和桌面物体摆法会直接改变抓取难度。每种控制方法在同一布局上独立起跑，才能逐场景比较组合前后发生了什么。查看叠衣录像时，先找夹爪合拢的画面，再看衣角有没有随抬臂移动。如果衣角留在桌面，就要重新定位抓取点。下一次观测把这个接触结果带回控制器，让它有机会修正后续动作。桌面整理则要同时看成功数和部分分数，以区分已放好部分物品和完成整项任务。[原理导读与 16×14 候选练习](00-原理导读.md)

## 重跑同一条已保存动作

在本专题运行 `python3 reproduce.py`，先核对 `reproduction-output/report.json` 中的 456 步记录和场景编号。本节的轨迹来自 `fold_clothes__random__g0__l0` 的组合回合，归档包含执行过的关节命令和逐步观测状态。完整的仿真环境需要 RoboDojo 的 Isaac Sim 5.1、资产和冻结布局。[RoboDojo](https://github.com/robodojo-benchmark/RoboDojo) · [上层控制器安装](https://github.com/anonymous-report-421/eval-of-gpt-6-astra-as-policy)

在外部依赖目录检出对应版本。控制器补丁以其原始 MIT［开源许可证］条款提供。工作目录应为独立检出。先把 `TOPIC`、`ROBODOJO_ROOT`、`ASTRA_ROOT` 和 `SIM_PYTHON` 设置为下文所述的绝对路径，并导出这些变量供一键入口读取。

```bash
export ROBODOJO_ROOT
git -C "$ROBODOJO_ROOT" checkout ee67a1468510da7624a089164402359f2afc72c8
git -C "$ASTRA_ROOT" checkout 8f3d362b077d8efb77e2a7274d5b2c20e2243846
git -C "$ASTRA_ROOT" apply "$TOPIC/code/robodojo/g05-controller.patch"
export PYTHONPATH="$TOPIC/code/robodojo:$ASTRA_ROOT:$ROBODOJO_ROOT:$ROBODOJO_ROOT/XPolicyLab"
export ROLLOUT_STUDENT=g05
export ROLLOUT_EVAL_MANIFEST_SHA256=9641fa252856c5ffc07b269c9fef4fed7f5bbc91b45ea0e93fe2a39fa73944b7
PANEL="$ASTRA_ROOT/hybrid_rollout/robodojo/eval_panels/robodojo_panel60_v1.json"
RUN=$(mktemp -d)
echo "$RUN"
python3 "$TOPIC/code/robodojo/select_case.py" --panel "$PANEL" \
  --case fold_clothes__random__g0__l0 --output "$RUN/case.json"
cd "$ROBODOJO_ROOT"
"$SIM_PYTHON" -m hybrid_rollout.robodojo.robodojo_server.server \
  --task fold_clothes_random --output "$RUN/sim" \
  --eval-manifest "$PANEL" --case-file "$RUN/case.json"
```

`TOPIC`、`ROBODOJO_ROOT`、`ASTRA_ROOT` 分别指专题目录和两个外部仓库的绝对路径。`SIM_PYTHON` 指仿真环境的解释器。另一个终端使用相同环境变量及上面打印或保存的 `RUN`，等待服务输出 `"event": "ready"` 后运行：

```bash
"$SIM_PYTHON" "$TOPIC/code/robodojo/replay_actions.py" --report "$RUN/replay.json"
```

看 `observed_steps`、`terminal` 和关节状态差，原生分数在 `$RUN/sim/evaluation_outcome.json`。本次复验执行 456 步并成功结束，原生分 1.0，归档与复验关节状态最大绝对差为 0。[实际复验记录](data/fold/native-replay-check.json)回放完成后关闭自己启动的服务。

以上环境准备完成后，从本专题目录也可以一条命令启动、回放和关闭自己的进程。环境变量需已导出，输出目录需为新目录：

```bash
python3 simulation_replay.py fold --output ./reproduction-output/fold-native
```

## 换成新推理

准备单独的 G0.5 推理环境。历史仿真环境和 G0.5 适配器位于独立检出。按[官方适配文档](https://github.com/robodojo-benchmark/RoboDojo/tree/main/XPolicyLab/policy/G05)下载仿真检查点并设置处理器、动作分词器和数据统计文件。[检查点发布页](https://huggingface.co/OpenGalaxea/g05-robodojo)

将 [XPolicyLab](https://github.com/XPolicyLab/XPolicyLab) 检出到 `5ea94071689e397980ca3ec25061b5f4557d9eff`，按其说明初始化 G0.5 子目录并配置依赖。 `G05_XPOLICY_ROOT` 指该检出目录。启动服务前把它的父目录置于模块搜索路径首位，让控制器和仿真记录使用固定版本的 RoboDojo，模型进程使用带 G0.5 的适配器：

```bash
export G05_XPOLICY_ROOT
export PYTHONPATH="$(dirname "$G05_XPOLICY_ROOT"):$PYTHONPATH"
```

每个回合使用新输出目录并重启仿真服务。 `POLICY_PYTHON` 指策略解释器，`G05_CKPT_PATH` 指解压后的 `checkpoints/checkpoint`。仿真输出目录与 `case.json` 在同一级。

```bash
"$POLICY_PYTHON" -m g05_astra.student --checkpoint "$G05_CKPT_PATH" \
  --identity-output "$RUN/policy-identity.json"
```

服务输出就绪后，从另一个终端运行仅 G0.5 控制器：

```bash
"$POLICY_PYTHON" "$TOPIC/code/robodojo/astra_baseline.py" \
  --checkpoint "$G05_CKPT_PATH" --output "$RUN/controller"
```

组合组将上一条命令替换为下列控制器。`CODEX_BIN` 为有模型权限的命令行程序；`CODEX_HOME` 使用自己的隔离配置。仅上层推理将 `--evaluation-method` 改为 `gpt_only`，跳过 G0.5 服务。场景切换时从 `case-plan.json` 读取相应 `runtime_task` 与 `reset_seed`。

```bash
export ROLLOUT_CONTEXT_REVISION=structured_v1
"$POLICY_PYTHON" -m hybrid_rollout.robodojo.skill.run \
  --task fold_clothes_random --checkpoint "$G05_CKPT_PATH" \
  --codex "$CODEX_BIN" --evaluation-method g05_plus_gpt --seed 0 \
  --max-decisions 0 --output "$RUN/controller"
```

先核对 `policy-identity.json` 的检查点散列和 16 步动作长度，再查看终局回执。候选张量示例在 [proposal-example.json](data/fold/proposal-example.json)。
