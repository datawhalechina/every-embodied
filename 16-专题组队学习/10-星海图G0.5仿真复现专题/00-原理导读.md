# 00 · 从相机观测到闭环动作

看机器人弯下手指、拉开抽屉或折起衣角时，可以追问三个问题。它刚看到了什么？下一段动作由谁决定？什么测量能确认动作生效？这三个问题分别对应观测、控制和验证，也能用来读本专题的代码与录像。

## G0.5 怎样从观测生成动作

G0.5 是一种 VLA［视觉—语言—动作模型］。任务指令给出意图，相机图像提供物体外观和位置线索，本体状态提供关节角、夹爪开度等机器人自身的测量。模型还需要知道当前使用的机器人类型，因为同一个“合拢夹爪”在不同硬件上有不同的动作表示。论文用同一个自回归解码器生成结构化推理词元和动作词元。自回归意味着每一步依据前面已经产生的内容预测下一个词元，所以当前子任务或目标框可以成为后续动作生成的条件。论文还用跨秒视觉历史补充单帧图像缺少的运动信息。[G0.5 论文](https://arxiv.org/abs/2608.11739) · [官方实现](https://github.com/OpenGalaxea/GalaxeaVLA)

训练中使用的动作词元是一种便于模型学习的表示。真正发送给仿真器的是适配器还原、校验后得到的连续数值。论文介绍了统一词元生成的模型设计。本专题的 RoboDojo 实验明确使用 `action_source='fm'` 对应的连续动作路径，万圣节候选程序则提供原生推理开启与关闭两种设置。阅读实验时应先确认实际使用的输出模式、检查点和适配器版本。[RoboDojo 策略服务](code/robodojo/g05_astra/student.py) · [万圣节候选程序](code/roboharness/g05_worker.py)

```text
任务指令 + 相机图像 + 本体状态
  → 策略生成动作候选
  → 按机器人动作接口还原和校验
  → 执行一小段并取得新观测
  → 根据接触、目标位置或关节状态决定继续、修正或换阶段
```

## 为什么只执行候选动作的一部分

一次预测一段动作，可以把接近、抓取、抬起等连续运动组织起来。在 RoboDojo 中，候选是 16 行、每行 14 个数。左右臂各占 6 个关节值和 1 个夹爪开度。仅 G0.5 的控制器每次最多执行前 15 步，然后重新拍摄图像、读取关节状态并预测下一段。这是滚动时域控制。自由空间里可以走较长一段，临近接触时则值得更早检查，例如衣角在夹爪合拢前是否已滑走。上层控制参与时，可以接收候选、缩短执行前缀，或使用有界末端修正。[叠衣服与桌面整理](02-叠衣服与桌面整理.md) · [固定前缀控制器](code/robodojo/astra_baseline.py)

万圣节例子把候选和当前回合、观测序号一起记录。机器人一旦转动底盘或移动抽屉，旧相机姿态和旧目标位置就可能改变。执行前核对序号可防止用从过时画面生成的动作控制当前机器人。已发布的短动作执行器上限为 8 步，可逐步检查执行回执和目标进展。这个 8 步上限属于万圣节的适配器，RoboDojo 的 15 步属于它自己的控制器，两者的夹爪数值含义也由各自接口定义。[候选绑定与关节约束](code/roboharness/bridge.py) · [短动作执行器](code/roboharness/g05_chunk_20261106.py)

## 三个案例怎样分工

| 案例 | 动作由谁决定 | 该看哪条证据 |
| --- | --- | --- |
| 双手弹琴 | G0.5 提供双臂姿态参考，逆运动学求满足目标手腕位置与方向的关节构型，专用演奏控制器负责指法和节拍。 | 手腕到位误差检查是否对准，琴键关节的触发序列检查是否真的按到了目标键。 |
| 叠衣服与桌面整理 | 动作策略给出局部动作，上层控制在组合组里决定采纳、缩短还是修正。 | 比较同一初始布局上的原生成功与部分得分，再看抓取或放置时的观测。 |
| 万圣节收纳 | 上层推理选择子任务与目标，几何工具定位和导航，G0.5 在满足条件的局部操作阶段提供候选。 | 跟踪目标是否真的移动、物品是否在抽屉内，以及原生终局分数。 |

弹琴的手腕目标来自已知钢琴几何。移琴后需要更新目标，再求出可达的手腕姿态。厨房抽屉的目标则可从画面选取，结合深度和相机位姿估计其在机器人坐标系中的位置。两个例子都要检查测量误差，因为手腕对准、夹爪闭合和物体被稳定抓住分别对应不同的物理状态。[弹琴策略接入](../../06-策略抓取或抓取VLA/大模型控制、VLA、VLM/20-GPT6-Astra机器人弹琴与上下文工程/G05.md) · [万圣节阶段交接](03-万圣节收纳.md)

## 怎样读懂复现结果

**数据复核**读取既有回合的记录并重新统计。**物理回放**把保存的关节目标送回仿真，用新的物理状态验证动作效果。**闭环重跑**用实时观测重新调用策略，后续动作可以随场景变化。这三种做法分别回答统计是否正确、同一轨迹能否重复执行、策略能否重新完成任务。

叠衣服可以用同一布局的三种方法做配对比较。整理桌面三组均为 0/5 次成功，其中组合组平均原生分 0.70，读者可以据此区分部分完成和整项成功。万圣节的三条路径都在实例 301 获得原生分 1.0，无原生推理路径沿用一部分早期轨迹后续跑，同时各路径的上层推理与阶段流程有所差异。比较这些记录时，可以描述同一任务上的步数和词元差异，判断某个开关的独立影响则需要在其余条件一致时另做对照。[叠衣逐回合评测](data/fold/episodes.csv) · [万圣节原生记录](data/halloween/native-outcomes.json)

## 用归档数据练习

在专题目录运行下面的命令，检查一条实测叠衣候选中的行列和夹爪范围。它只读取归档文件。

```bash
python3 - <<'PY'
import json
from pathlib import Path

sample = json.loads(Path("data/fold/proposal-example.json").read_text())
actions = sample["actions"]
assert len(actions) == 16 and all(len(step) == 14 for step in actions)
assert all(0 <= step[i] <= 1 for step in actions for i in (6, 13))
print("候选形状", len(actions), len(actions[0]))
print("首步左右夹爪开度", actions[0][6], actions[0][13])
PY
```

看到 `16 14` 后，打开叠衣组合组的录像，找一个夹爪合拢的画面，再看衣角在后续画面里有没有跟随夹爪抬起。候选里的开度是控制目标，下一帧的衣角位置才提供抓取结果的证据。[叠衣录像与时间截图](02-叠衣服与桌面整理.md#回放视频与时间截图)
