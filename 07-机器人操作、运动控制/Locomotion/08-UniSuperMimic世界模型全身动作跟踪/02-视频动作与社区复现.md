# SuperMimic 社区复现：从视频动作到机器人策略

本章介绍如何从单人视频生成 G1 参考动作，选择社区实现训练和评测，并了解加速训练、灵巧手和真机部署。完整项目清单见[社区项目完整合集](./03-SuperMimic社区项目完整合集.md)。本章整理自公开文档和代码，命令与结果均标明来源；以下训练流程尚未在本教程环境中运行。

SuperMimic 的训练循环由物理仿真产生状态转移，世界模型拟合这些转移；策略在模型中展开短轨迹并通过模型获得梯度。原论文作者、各社区项目的开发者和本教程是不同来源，项目表格中的性能数字均为对应项目作者的报告。

## 2. 视频怎样变成机器人能跟踪的动作

```text
单人视频 → 每秒 30 帧 → 人体姿态与根部运动重建
         → 逆运动学映射到 G1 → 关节限位、脚底接地检查
         → 机器人参考动作 → 仿真训练 → 完整片段评测
```

人体和 G1 的骨骼尺寸、关节数量和活动范围不同；视频中还会出现遮挡和运动模糊。因此，视频重建后的关节轨迹需要检查连续性和物理可行性。跟踪策略学习的是如何在物理仿真中执行参考动作；如果目标是主动击球，还要增加球和球拍的状态、动作时机、交互物理及任务奖励。

### 2.1 环境和输入

先准备 Linux、NVIDIA 显卡及其驱动、`git`、`ffmpeg` 和 `uv`。上游推荐从 **5–20 秒、全身可见的单人视频**开始；原视频需要有使用授权。比赛视频包含两名球员时，应先裁剪并确认目标人物，镜头切换与遮挡可能影响重建。

本节固定 [NJU 项目版本](https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real/tree/f8f60d7bbdba68468c050ef100af02d752ca238e)、[GVHMR 版本](https://github.com/zju3dv/GVHMR/tree/ee960bb6e2ea2d381aa97f08e9b71ef320b624b1)和 [GMR 版本](https://github.com/YanjieZe/GMR/tree/25f56db79ac411258b377b6d4ccba0c8ff3372ac)。GVHMR 与 GMR 依赖版本不同，需要分别准备环境；人体模型、网络权重与项目源码也分别遵循各自的使用许可。

设置工作目录，下面的变量均可改为自己的路径，视频和模型放在教程仓库之外：

```bash
export DATA_ROOT=/path/to/robot-data
export V2M_HOME="$DATA_ROOT/supermimic-video"
export V2M_WORK="$V2M_HOME/work"
mkdir -p "$V2M_HOME" "$V2M_WORK" "$DATA_ROOT/envs"

git clone https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real.git "$V2M_HOME/SuperMimic-Repro-Sim2Real"
git clone https://github.com/zju3dv/GVHMR.git "$V2M_HOME/GVHMR"
git clone https://github.com/YanjieZe/GMR.git "$V2M_HOME/GMR"

git -C "$V2M_HOME/SuperMimic-Repro-Sim2Real" checkout f8f60d7bbdba68468c050ef100af02d752ca238e
git -C "$V2M_HOME/GVHMR" checkout ee960bb6e2ea2d381aa97f08e9b71ef320b624b1
git -C "$V2M_HOME/GMR" checkout 25f56db79ac411258b377b6d4ccba0c8ff3372ac
```

按上游[环境配置与模型清单](https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real/blob/f8f60d7bbdba68468c050ef100af02d752ca238e/docs/VIDEO_TO_MOTION.md#environment-setup)准备三个环境：项目训练环境、GVHMR 环境、GMR 环境。视频转换还需要自行获取并放置 GVHMR 权重、人体模型 SMPL-X 及其依赖；SMPL-X 需要注册并遵循其许可。上游对无图形服务器还列出一处 GVHMR 兼容性补丁和渲染配置。

例如，项目环境可使用独立路径；具体依赖安装仍以上游文档为准：

```bash
cd "$V2M_HOME/SuperMimic-Repro-Sim2Real"
export UV_PROJECT_ENVIRONMENT="$DATA_ROOT/envs/supermimic-repro"
uv sync
```

### 2.2 生成 G1 动作及对照视频

以下在 NJU 项目根目录运行；`GVHMR_PY` 和 `GMR_PY` 分别指向准备好的两个环境的解释器，视频路径替换为实际文件：

```bash
cd "$V2M_HOME/SuperMimic-Repro-Sim2Real"
export GVHMR_ROOT="$V2M_HOME/GVHMR"
export GMR_ROOT="$V2M_HOME/GMR"
export GVHMR_PY="$DATA_ROOT/envs/gvhmr/bin/python"
export GMR_PY="$DATA_ROOT/envs/gmr/bin/python"
tools/video2motion/run_pipeline.sh /path/to/single_person.mp4
```

上游流程默认按固定相机处理。输出包括：

| 输出 | 内容 |
| --- | --- |
| `$V2M_WORK/video30/` | 重采样为每秒 30 帧的视频。 |
| `$V2M_WORK/gvhmr/` | 人体动作重建结果及日志。 |
| `$V2M_WORK/csv_drift/` | 去除高度漂移的 G1 参考动作，以及对应的重定向数据。 |
| `$V2M_WORK/csv_constant/` | 使用固定地面偏移的另一版本。 |
| `$V2M_WORK/preview/` | 原视频与 G1 动作的并排预览。 |

检查预览中人物朝向、手脚位置和动作节奏是否对应。脚部穿地、快速挥拍时手臂抖动、人物被遮挡或识别错人，都应先调整视频片段或重建设置。切镜头较多时可参考上游 `SHOTS` 选项；移动摄像机需要另行处理相机运动，不能直接假定固定相机。

### 2.3 在 NJU 实现中准备训练数据

上游输出的动作是无表头、每秒 30 帧的 36 列文件：根部位置 3 列，根部旋转四元数 `xyzw` 4 列，29 个关节位置。上游训练流程还会转换成每秒 50 帧的数据格式：

```bash
cd "$V2M_HOME/SuperMimic-Repro-Sim2Real"
uv run python scripts/data/csv_to_npz_batch.py \
  --input-dir "$V2M_WORK/csv_drift" \
  --output-dir "$V2M_HOME/data/npz/my_motion" \
  --input-fps 30 --pattern '*.csv'
```

该命令只生成训练数据；如何构建动作库、从检查点微调和评测，见上游[自定义动作说明](https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real/blob/f8f60d7bbdba68468c050ef100af02d752ca238e/docs/CUSTOM_MOTIONS.md#csv--training-and-deployment)。先检查关节速度、脚部高度和根部轨迹，再选择训练片段。上游还提供动作拼接及关节速度限制工具。

### 2.4 接入 Uni-SuperMimic

NJU 的 `.npz` 是它自身训练流程使用的格式；Uni-SuperMimic 的普通动作加载器读取 36 列 `.csv`。对照固定版本的 [NJU 关节列表](https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real/blob/f8f60d7bbdba68468c050ef100af02d752ca238e/src/supermimic/data/motion_convert.py)与 [Uni-SuperMimic 关节列表](https://github.com/Motphys/Uni-SuperMimic/blob/d78a5e2bc26ee26c3a94ae10418b7fb9018836ee/src/unisupermimic/tasks/motion_tracking/g1/supermimic/robot.py)，两边的 **29 个关节名称和顺序一致**；根部旋转输入均为 `xyzw`，默认源帧率均为 30。应继续检查具体文件的坐标方向、尺度和物理动作质量。

准备好 Uni-SuperMimic 的模型资源与环境后，可在其仓库根目录使用一个重建动作作为训练参考。下面 `single_person.csv` 是示例文件名；需替换为实际生成的文件：

```bash
cd /path/to/Uni-SuperMimic
export UV_PROJECT_ENVIRONMENT="$DATA_ROOT/envs/uni-supermimic"
export MOTION_CSV="$V2M_WORK/csv_drift/single_person.csv"
test -f "$MOTION_CSV"
uv run unisupermimic-train \
  "env.commands.motion.motion_files=['$MOTION_CSV']" \
  env.commands.motion.src_fps=30 \
  "training.log_dir=$V2M_HOME/runs/video-motion"
```

这里覆盖的是参考动作列表，其他训练参数沿用所安装版本的配置；单个动作训练与多动作训练是不同实验。训练后使用所生成的匹配检查点，并按[上游评测入口](https://github.com/Motphys/Uni-SuperMimic#evaluation)检查完整片段和失败帧。以上跨仓库接入根据固定版本的配置与源码整理，运行结果需由实际训练和评测产生。

## 3. BlinkMimic：快速训练动作跟踪

BlinkMimic 基于社区复现改进采样、世界模型和训练实现。其作者在固定版本的报告中，使用单张 RTX 4090、三个随机种子，在 40 条 LAFAN1 训练动作上平均约 3.4 分钟达到指定回报与连续三个检查点零失败的条件；训练计时不含进程启动和离线评测。完整设置与同机对照见[结果说明](https://github.com/fuyichen0725/blinkmimic/blob/d264658d6c9ce61fb52f9f0f8985a369f3ccc409/README.md#results)。

上游要求 Linux、支持 CUDA 12.8 的 NVIDIA 驱动、`uv` 和 40 条 G1 动作资源。在独立目录中准备源码和环境：

```bash
export DATA_ROOT=/path/to/robot-data
git clone https://github.com/fuyichen0725/blinkmimic.git "$DATA_ROOT/blinkmimic"
cd "$DATA_ROOT/blinkmimic"
git checkout d264658d6c9ce61fb52f9f0f8985a369f3ccc409
export UV_PROJECT_ENVIRONMENT="$DATA_ROOT/envs/blinkmimic"
uv sync
tools/download_data.sh
uv run python tools/test_env.py
```

上游测试检查运动学、仿真状态往返和参考动作回放。确认环境及资源可用后，按[上游训练脚本](https://github.com/fuyichen0725/blinkmimic/blob/d264658d6c9ce61fb52f9f0f8985a369f3ccc409/README.md#train-evaluate-reproduce)训练并评测：

```bash
cd "$DATA_ROOT/blinkmimic"
bash scripts/train.sh "$DATA_ROOT/runs/blink-s0" --seed 0
uv run python tools/eval_batch.py --run_dir "$DATA_ROOT/runs/blink-s0" --group 18 --reps 4
uv run python tools/time_to_target.py "$DATA_ROOT/runs/blink-s0"
```

训练日志与检查点在指定运行目录；完整复现实验还需要多个随机种子。检查回报、完整动作是否失败、评测是否从首帧开始，以及记录训练和评测各自耗时，才能比较不同实现。上游提示共享显卡运行时异步探测选项可能出错，具体调整见项目文档。

## 4. Sharpa：把世界模型用于灵巧手

[Sharpa SuperMimic](https://github.com/Mingrui-Yu/sharpa_rl_unilab/tree/2d6bbe98aaa59216aedd9fba2b57196e830ef722)研究 22 自由度 Sharpa Wave 灵巧手在手内旋转圆柱体。它提供多种仿真后端及算法，默认路线先训练教师，再蒸馏学生；也提供直接训练仅使用可测观测历史的单阶段策略。

上游内置抓取缓存。完成其[安装与验证](https://github.com/Mingrui-Yu/sharpa_rl_unilab/blob/2d6bbe98aaa59216aedd9fba2b57196e830ef722/README.md#installation-and-validation)后，在该仓库根目录运行：

```bash
uv run sharpa-train --algo supermimic algo.single_stage=true
```

该配置输出 `policy_final.pt` 和训练日志；默认输出目录在 `logs/` 下。使用实际训练目录替换下面的路径后，可运行：

```bash
uv run sharpa-eval --checkpoint /path/to/policy_final.pt
```

作者在固定场景仿真中报告单张 RTX 4090、3,000 次迭代约 686 秒；单阶段策略的回报、旋转速度和掉落率使用其自身的固定场景评测口径。训练命令、后端、教师与学生的区别见[训练文档](https://github.com/Mingrui-Yu/sharpa_rl_unilab/blob/2d6bbe98aaa59216aedd9fba2b57196e830ef722/docs/en/training.md)。

## 6. 羽毛球动作与真正击球

视频转动作适合研究步伐、转身和挥臂的参考运动。要研究对来球的反应，可以对照另一项独立研究 [Humanoid Badminton](https://sunlight02.github.io/humanoid-badminton/)：该项目展示 G1 真机正手、反手、跳跃回球和人机连续对打，并使用分层技能学习处理来球和球拍动作。项目使用的方法与 SuperMimic 社区复现分别介绍，视频来源和具体实验条件见项目主页。

## 7. 评测时需要保存什么

保留输入视频及使用许可、参考动作文件与帧率、机器人模型与关节顺序、环境配置、训练检查点、训练时长、评测动作列表、失败判定及回放视频。遇到动作不自然，先对照人体与机器人重定向视频；若重定向已经正确，再检查仿真中的跟踪误差、接触和策略稳定性。对未参与训练的片段单独评测，可以了解策略面对新动作时的表现。
