本文参考用户提供的《VLA 图像 backbone 如何选择》的调研思路：每个环节先明确“要做什么决策”，再逐个拆机体检，用固定维度对比，最后按场景给选型与“明确不要做”。来源 S1–S24；外部材料未独立复核。论文全表与榜单见 02-论文与评测.md。

0. 调研方法：四步拆机

  1. 本节要做的决策：这个环节到底在选什么，选错的代价是什么。
  2. 候选逐个拆机：本体 / 机制 / 关键能力 / 成本 / 评级。
  3. 对比总表：固定维度，避免“各有千秋”式空话。
  4. 结论与建议：按场景排序，再给“求稳 / 求新 / 明确不要做”。

评级说明：★ 是本文基于现有材料的判断，不是论文指标；延迟与成功率来自来源，未在本机复测。带【索】的数字来自社区索引，带【推】的是来源作者的推断。

1. 动作表示：四条路线怎么选

1.1 本节要做的决策

控制频率有多高？动作是否多峰？要不要复用 VLM 词表？需不需要跨本体？这四个问题决定动作表示，而不是“哪种最新”。

1.2 逐个拆机

① 离散 token / 分类（RT-1、RT-2）

  • 本体：RT-1 用 EfficientNet + Transformer，35M，动作每维 256 bins，约 3Hz；RT-2 用 PaLI-X/PaLM-E，55B，动作直接生成文本 token，低于 1Hz。
  • 机制：把动作变成分类或语言 token，复用 VLM 的词表与自回归解码。
  • 能力：语义泛化强，适合语言条件复杂、长程的任务；高频控制弱。
  • 成本：RT-1 便宜；RT-2 的 55B 推理很贵。
  • 评级：RT-1 ★★★☆；RT-2 ★★★（能力上限高，但慢）。

② 连续回归 / 动作块（ACT、OpenVLA）

  • 本体：ACT 51.55M，ResNet18 + CVAE + Transformer，一次预测 10 步；OpenVLA 7B 级，SigLIP/DINOv2 + LLaMA-2，输出 7 维连续动作。
  • 机制：直接回归连续动作，或用动作块降低推理频率。
  • 能力：平滑、低延迟，适合高频控制；多峰动作分布难建模。
  • 成本：ACT 单卡 30–60 分钟；OpenVLA 约 10.3GB 显存。
  • 评级：ACT ★★★★★（入门首选）；OpenVLA ★★★★（开源部署友好）。

③ 扩散 / flow matching（DiT4DiT、DM0.5、PRTS、Dexora）

  • 本体：DiT4DiT 10.64B、只训 1.53%；DM0.5 6B；PRTS Qwen3-VL-4B + flow expert；Dexora diffusion transformer。
  • 机制：学习速度场或去噪过程，生成动作序列。
  • 能力：适合多峰、连续动作；推理步数与延迟更贵。
  • 成本：DiT4DiT 建议 ≥48GB 显存；DM0.5 的 9.29× 部署栈未完整公开。
  • 评级：★★★★（2026 年主流动作头，但要算延迟）。

④ 残差向量量化（RVQ，G0.5 ActionCodec）

  • 本体：G0.5 用 Qwen3.5 2B + 27 维共享动作空间 + residual vector quantizer。
  • 机制：把异构动作映射到共享空间，多轮残差量化成 token，自回归 decoder 生成后由 action decoder 重构。
  • 能力：共享离散空间，支持异构本体与多轮精修；只对 active motion groups 出 token。
  • 成本：需要 tokenizer/decoder 配套；码本与量化层数影响精度。
  • 评级：★★★★（目前只有 G0.5 一条本地证据）。

1.3 对比总表

路线代表表达连续/多峰推理成本跨本体代码成熟度拆机价值
离散 tokenRT-1、RT-2256 bins / 文本 token弱低 / 极高弱 / 中高 / 无★★★☆
连续 / 动作块ACT、OpenVLA连续 7 维 / 10 步块中低中 / 强高★★★★

1.4 结论与建议

  • 高频控制：优先连续/动作块或 flow；RT-2 的文本 token 低于 1Hz，不适合直接上高频回路。
  • 语言条件复杂、长程：离散 token 仍是最稳的语义接口；RT-2 的联合微调思路值得学。
  • 跨本体：RVQ 和统一动作空间最有潜力，但目前只有 G0.5 一条证据。
  • 求稳：ACT 入门，OpenVLA 看部署；求新：RVQ-head 的系统比较；明确不要做：拿 RT-2 的 55B 文本 token 去追 20Hz 控制。

2. 图像 backbone：拆机体检

2.1 本节要做的决策

VLA 的“眼睛”选谁：要几何还是语义？能不能进 32Hz 控制回路？许可是否允许商用？这一节直接采用用户提供的知乎拆机文章（S24）的框架。

2.2 逐个拆机

① DINOv3 —— 生来就是 backbone

  • 本体：ViT-B/L，86M/0.3B；自监督 + Gram anchoring。
  • 能力：几何稠密强（分割 55.9、深度 RMSE 0.309、NAVI 64.4），2–10ms。
  • 短板：没有语义对齐，需要下游交互模块补。
  • 评级：★★★★★ 首选主眼。

② Perception Encoder（SAM3 的塔）—— 本轮黑马

  • 本体：约 450M，1024px 输入，1024 维特征；对比学习 + 稠密自监督双目标。
  • 能力：几何接近 DINOv3，语义接近 CLIP，是“单塔兼得”的候选。
  • 成本：1024px 下 15–30ms，进 32Hz 要降到 224–448px 并重验特征。
  • 评级：★★★★☆ 潜力股，需自己降分辨率。

③ SigLIP-2（Qwen3-VL 的塔）—— 语义副塔

  • 本体：304M/400M，NaFlex 原生分辨率，图文对比。
  • 能力：语义对齐好；几何弱（分割 42.7、NAVI 49.4、深度 RMSE 0.494），5–12ms。
  • 评级：★★★☆ 适合双塔里的语义眼，不适合单独当主眼。

④ Swin（GroundingDINO 的塔）—— 不合格

  • 本体：Swin-T 28M / Swin-B 88M，检测框监督。
  • 问题：任务特化、层级窗口破坏全局 patch 网格、2023 年设计。
  • 评级：★☆ 拆出来没有意义；GroundingDINO 的价值在检测头 + BERT。

⑤ MoonViT（LocateAnything 的塔）—— 有等价平替

  • 本体：约 400M，SigLIP 族 NaFlex 变体。
  • 结论：拆出来与 SigLIP-2 没有本质差别，直接用 SigLIP-2 原版更干净。
  • 评级：★★★ 没必要抠。

⑥ AM-RADIO / Theia / DINOv2 —— 备选

  • AM-RADIO：0.4–1B，聚合蒸馏，几何语义双高（53.1 / 0.340 / 59.5），6–15ms，GR00T N1 同款，★★★★ 单塔方案。
  • Theia：26–86M，多教师蒸馏，1–3ms，★★★★ 边缘端。
  • DINOv2：304M，4–8ms，上代几何王，★★★ 已被 DINOv3 取代。

2.4 结论与建议

  • 高频控制/几何任务：DINOv3 ViT-B；极端边缘用 Theia 或 DINOv3 ViT-S。
  • 语言条件复杂：DINOv3 + SigLIP2-Base 双塔（OpenVLA 验证过的配方）。
  • 单塔、算力宽裕：AM-RADIO；LLM-centric 复现：SigLIP-2 / PaliGemma，跟随原架构。
  • 求稳：DINOv3 ViT-B 单塔起步，语义不够加 SigLIP2-Base；求新：PE vs DINOv3 vs 双塔的对照消融。
  • 明确不要做：从 Qwen3-VL/LocateAnything 里抠塔（有同源平替、许可问题）；从 GroundingDINO 抠 Swin（表征不合格）；把 SAM3/LocateAnything 整模型当“眼睛”（它们是任务模型/慢层工具）。

3. 训练范式：SFT、RL 与在线适应

3.1 本节要做的决策

你是在做“能跑通的策略”，还是“部署后继续变好的系统”？前者看 SFT，后者看 RL 与在线适应；两者的数据与算力差一个量级。

3.2 逐个拆机

① SFT / 联合微调（RT-2、OpenVLA、SmolVLA、ACT）

  • 数据：示教轨迹；算力：单卡到多卡；改基座：是；部署后继续学：否。
  • 评级：★★★★★ 入门与复现首选。

② RL 预训练（PRTS）

  • 本体：Qwen3-VL-4B + flow expert + contrastive RL；约 167B tokens、64 张 H100。
  • 能力：LIBERO 98.4；改基座；部署后不直接继续学。
  • 评级：★★★☆ 研究向，算力门槛高。

③ 机群 offline-to-online RL（LWD）

  • 本体：16 台 AgiBot G1、8 个真实任务、652.5h 离线 buffer；平均 95%。
  • 成本：多机器人、调度、在线 replay、人类接管接口。
  • 评级：★★★ 工业向，不是单机可复现。

④ 后置在线适应（Agentic-VLA）

  • 本体：OpenVLA-OFT + Experience Memory + LGE + ARS + GRPO；4 张 A100，LIBERO 97.8。
  • 能力：不改基座，部署后可在仿真里继续学；真机未验证。
  • 评级：★★★★ 部署向，性价比高。

⑤ 工程化 RL 后端（Dexbotic-RLinf）

  • 本体：Dexbotic + RLinf，PPO 在线微调；1 节点 8 GPU；章节未给成功率。
  • 评级：★★★ 工程集成，适合已有 Dexbotic 栈的团队。

⑥ 质量感知训练（Dexora）

  • 本体：discriminator 给 diffusion loss 加权；basic 约 90%，dexterous 66.7% vs 51.7%。
  • 评级：★★★★ 数据质量路线，值得借鉴。

3.3 对比总表

范式代表数据需求算力改基座部署后继续学证据强度拆机价值
SFT / 联合微调RT-2、OpenVLA、ACT中低–中是否强★★★★★
RL 预训练PRTS高64×H100是否强★★★☆
机群 offline-to-onlineLWD极高多机器人是是中★★★
后置在线适应Agentic-VLA中4×A100否是（仿真）中★★★★
工程化 RL 后端Dexbotic-RLinf中8 GPU否是弱（无数字）★★★
质量感知训练Dexora中中是否中★★★★

3.4 结论与建议

  • 入门/复现：SFT + ACT/OpenVLA；先把数据、评测、显存跑通。
  • 部署后继续变好：Agentic-VLA 这类后置外环优先；不要一上来做机群 RL。
  • 研究：PRTS 的 RL 预训练值得读，但先确认 64×H100 的算力。
  • 求稳：SFT；求新：后置在线适应 + 质量感知；明确不要做：没有评测与安全策略就上 RL。

4. 3DGS × VLA：四种结合方式

4.1 本节要做的决策

3DGS 是当数据引擎、场景表示、世界模型，还是直接当图像塔？前三种有工程路径，第四种目前是空位。

4.2 逐个拆机

① 数据引擎（LEGS、Action-View、EmbodiedSplat、RoboGSim）

  • 本体：3DGS 重建场景 + SAM3D mesh / 轨迹优化；LEGS 在 G1 上 1,110 次真机试验、9/9 匹配遥操作，新外观适应成本约 1/15【索】。
  • 能力：不用遥操作也能造数据；不进策略网络。
  • 评级：★★★★★ 最实的路线。

② 场景表示（Embodied MM Grounding、Gaussian-LIC2）

  • 本体：语义高斯地图 / 3DGS SLAM；开放词汇定位、避障、站位选择。
  • 能力：把“看懂 3D”卸载到外部表示，缓解 VLA 的空间重绑定。
  • 评级：★★★★ 被低估。

③ 世界模型 / 动作场（GAF、GWM、GaussianWAM）

  • 本体：4D 高斯动作场 / 3DGS 世界模型 / 训练期教师；GaussianWAM 推理不渲染。
  • 能力：预演、model-based RL、训练期 3D 蒸馏。
  • 评级：★★★★ 训练耦合、部署丢弃。

④ 轻量化 3D 表征（CompactSplat）

  • 本体：前馈高斯 + 推理期稀疏度控制；端侧 3DGS。
  • 能力：让 3DGS 能在边缘跑；目前没有配 VLA。
  • 评级：★★★ 潜力，未验证。

⑤ 3DGS 作为图像塔

  • 现状：现有材料没有把 3DGS 渲染直接作为 VLA 视觉塔的论文。
  • 最接近：GaussianWAM（训练期教师）、Embodied MM Grounding（外部表示）、3DVLA（3D 特征增强）、CompactSplat（轻量 3DGS）。
  • 评级：★ 空位，需要外部检索/新论文。

4.3 对比总表

方式代表3DGS 角色进策略网络证据强度工程成本拆机价值
数据引擎LEGS、Action-View造数据否强中★★★★★
场景表示Embodied MM Grounding外部 3D 地图否（间接）中中★★★★
世界模型GAF、GWM、GaussianWAM预演/教师部分（训练期）中高★★★★
轻量 3DCompactSplat端侧 3DGS否弱中★★★
图像塔无视觉输入是无高★

4.4 结论与建议

  • 想快速见效：数据引擎；LEGS/Action-View 是目前最强的实证。
  • 想解决空间问题：场景表示；把 3D 从策略网络卸载到外部地图。
  • 想做研究：3DGS 直接当图像塔是空位，但先回答渲染延迟、显存、梯度链路三个问题。
  • 求稳：数据引擎；求新：3DGS-native 轻量 VLA；明确不要做：把 3DGS 渲染直接塞进 32Hz 回路而不做延迟预算。

5. 轻量化：参数、推理、数据三条路

5.1 本节要做的决策

你要降的是参数、延迟，还是数据成本？三条路的瓶颈不同，不能用一个“小模型”概括。

5.2 逐个拆机

① 参数小（SmolVLA 450M、Evo-1 0.77B、VLA-Adapter 0.5B）

  • Evo-1：InternVL3-1B + cross-modulated DiT flow；Meta-World 80.6、LIBERO 94.8、RoboTwin 37.8、xArm6 78%；RTX 4090D 2.3GB / 16.4Hz；无机器人预训练。
  • 评级：★★★★★ 单任务/边缘首选。

② 推理快（SpecVLA、FAST、VLAQuantBench、Multi-Teacher OPD）

  • SpecVLA 推测推理；FAST 用 DCT+BPE 压缩动作序列；VLAQuantBench 闭环比较 PTQ；OPD 多教师蒸馏。
  • 评级：★★★★ 不改参数即可降延迟。

③ 数据省（MiDAS）

  • 少量专家示范启动 → 自主试错 → 按结果筛选。
  • 评级：★★★ 数据成本路线。

④ 效率膝（EffVLA）

  • 文件称约 3.75B 是效率膝；VLM 初始化对齐 +7.1 点、零延迟【索】。
  • 评级：★★★ 选型参考，不是硬门槛。

⑤ TurboVLA

  • 本地章节与两份外部调研均未收录；需要 arXiv/项目页后补。
  • 评级：待补，不编造指标。

5.3 对比总表

路径代表参数/加速精度训练成本部署场景代码/权重拆机价值
参数小SmolVLA 450M、Evo-1 0.77B0.45–1B接近 3B中边缘/单任务✅★★★★★
推理快SpecVLA、FAST、VLAQuantBench推测/量化/蒸馏保持低–中已有模型加速部分★★★★
数据省MiDAS—逐步提升低数据稀缺待核★★★
效率膝EffVLA~3.75B参考高研究部分★★★
待补TurboVLA未知未知未知未知未知待补

5.4 结论与建议

  • 单任务/边缘：0.5–1B 足够；Evo-1 是当前最完整的 0.77B 证据。
  • 跨本体：0.5B 的极限没有系统答案；不要把单任务结果外推。
  • 已有大模型：先做推理加速/量化，再考虑换小模型。
  • 求稳：SmolVLA/Evo-1；求新：TurboVLA 与 RVQ-head 的交叉；明确不要做：只比参数、不比延迟与成功率。

6. 世界模型：WAM 与 3DGS 世界模型

6.1 本节要做的决策

世界模型是当训练期教师、部署期预演，还是当纯视频生成？只有前两者与 VLA 直接相关。

6.2 逐个拆机

① Efficient-WAM（1B）

  • 预测未来 + 动作；降低“想象未来”的成本；★★★★。

② Light-WAM

  • 状态融合动作解码；LIBERO 强、RoboTwin 多任务；★★★★。

③ InternVLA-A1.5

  • 2B + 460M expert，冻结 WAN 做 latent foresight；训练耦合、部署丢弃；★★★。

④ GAF / GWM / GaussianWAM

  • 4D 高斯动作场 / 3DGS 世界模型 / 训练期 3D 蒸馏；★★★。

⑤ 纯视频世界模型

  • 不在本节范围，见仓库 17-具身世界模型。

模型预测目标输出动作参数/延迟训练成本证据强度拆机价值
